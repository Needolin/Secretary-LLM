# Secretary-LLM — локальный секретарь

Учебный проект на Python. Сейчас в нём реализованы веб-интерфейс на Flask, хранение расписаний в JSON и `TaskAgent` для управления задачами.

> **Текущее ограничение:** поле «Отправить команду» пока не понимает свободный текст вроде «добавь тренировку в среду». Интерпретатор естественного языка и полноценное планирование ещё не подключены. Задачи можно реально создавать, читать, изменять и удалять через API `TaskAgent`.

## Как устроены данные

Все данные находятся в `Application/Database/schedules.json`. Это список расписаний. У каждого расписания есть `id`, `name`, `period` и список `events`.

У каждого элемента `events` есть поле `type`:

- `"event"` — обычное событие;
- `"task"` — задача с описанием, сроком (`deadline`), приоритетом (`priority`) и статусом (`status`).

Для обоих типов время начала и окончания необязательно. Если обе границы заданы, элемент показывается отрезком. Если указана только одна граница или время не задано, элемент показывается квадратным маркером. Если у элемента нет времени, его день берётся из `day_index` или (для задачи) из `deadline`. Если день неизвестен, в недельном/месячном виде элемент попадает в строку «Без дня».

Пример одного расписания:

```json
[
  {
    "id": 1,
    "name": "Учёба",
    "period": "Week",
    "events": [
      {
        "id": 1,
        "type": "event",
        "title": "Лекция по ИИ",
        "description": "Аудитория 301",
        "start_time_in_minutes": 600,
        "end_time_in_minutes": 660
      },
      {
        "id": 2,
        "type": "task",
        "title": "Подготовить лабораторную",
        "description": "Сделать отчёт",
        "deadline": "2026-10-28",
        "priority": "high",
        "status": "pending"
      }
    ]
  }
]
```

`start_time_in_minutes` и `end_time_in_minutes` — количество минут от начала периода расписания. Для недельного расписания, например, `600` означает понедельник в 10:00. ID элементов уникальны внутри одного расписания.

При чтении базы старые записи автоматически дополняются недостающими полями `type`, `id` и стандартными полями задач. Перед ручным редактированием `schedules.json` остановите Flask, чтобы не перезаписать данные.


## Как читать таймлайн

- В недельном виде у каждого дня недели своя горизонтальная линия; над линиями показаны отметки времени `06:00`, `12:00`, `18:00` и `22:00`.
- Событие с началом и концом изображается толстым отрезком между ними.
- При наведении курсора появляется подсказка с названием, началом, концом и описанием. Если интервалы перекрываются, в одной подсказке отображаются все элементы под курсором.
- Если времени не хватает хотя бы с одной стороны, вместо отрезка показывается квадрат. Для элемента без времени подсказка честно сообщает, что время не назначено.
- Цвета различают обычные события и задачи.
- **Перетаскивание:** зажми отрезок или квадрат и перемести его. По горизонтали время привязывается к часовым отметкам; у интервала сохраняется продолжительность, при этом к ближайшему часу прилипает ближайшая граница — начало или конец. По вертикали элемент переносится на другой день недели/месяца. Отпусти мышь, чтобы сохранить положение в `schedules.json`.
- Если у элемента не было временных границ, вертикальный перенос меняет только день. Горизонтальный перенос назначает ему время начала.
- **Клик по элементу** открывает окно редактирования рядом с курсором. В нём можно изменить название, день, время начала/конца, убрать временную границу пустым значением или удалить элемент.
- Если при сохранении сервер отклонит изменение, страница вернётся к данным из базы, а сообщение об ошибке появится внизу экрана.

## Требования

- Python 3.10 или новее.
- Зависимость приложения — Flask 3.x.

## Установка и запуск

Все команды выполняйте из корневой папки `Secretary-LLM`.

### Запуск

Заходим в корень проекта, устанавливаем зависимости и запускаем app.py
```bash
python -m pip install -r requirements.txt
python Application/Site/app.py
```

Откройте <http://127.0.0.1:5000> в браузере. Остановить сервер можно сочетанием `Ctrl+C` в терминале.

## Проверка приложения

Проверки используют временный JSON-файл и не должны менять ваше рабочее расписание.

```bash
python -m unittest discover -s tests -v
```

## API

Базовый адрес: `http://127.0.0.1:5000`. Для запросов с телом используйте JSON (`Content-Type: application/json`). Запросы можно отправлять через Postman, Insomnia или `curl`.

| Метод | Путь | Назначение |
|---|---|---|
| `GET` | `/health` | Проверить, что Flask запущен |
| `GET` | `/api/schedules` | Получить все расписания |
| `POST` | `/api/schedules` | Создать расписание |
| `GET` | `/api/schedules/<id>` | Получить одно расписание |
| `GET` | `/api/schedules/<id>/events` | Получить обычные события выбранного расписания |
| `PATCH` | `/api/schedules/<id>/items/<item_id>` | Изменить событие или задачу; используется перетаскиванием и окном редактирования |
| `DELETE` | `/api/schedules/<id>/items/<item_id>` | Удалить событие или задачу из окна редактирования |
| `GET` | `/api/tasks` | Получить задачи из всех расписаний или из выбранного через `?schedule_id=<id>` |
| `POST` | `/api/task-agent` | Выполнить действие `TaskAgent` |
| `POST` | `/api/command` | Передать текстовую команду оркестратору (пока без интерпретации естественного языка) |

### Изменить элемент таймлайна вручную

Для события или задачи используется один общий адрес по ID элемента:

`PATCH /api/schedules/1/items/2`

```json
{
  "day_index": 1,
  "start_time_in_minutes": 2400,
  "end_time_in_minutes": 2580
}
```

`day_index` начинается с нуля: для недельного расписания `0` — понедельник, `1` — вторник и т. д. Время задаётся абсолютными минутами от начала периода: `2400` — вторник в 16:00. Чтобы очистить одну временную границу, передайте её как `null`; чтобы удалить элемент, используйте `DELETE /api/schedules/1/items/2`. ID ищется внутри указанного расписания, а тип `task`/`event` определяется самой записью.

### Создать расписание

`POST /api/schedules`

```json
{
  "name": "Учёба",
  "period": "Week"
}
```

Допустимые периоды: `Day`, `Week`, `Month`. В успешном ответе вернётся созданное расписание и его `id`. Используйте этот ID в запросах к `TaskAgent`.

### Создать задачу

`POST /api/task-agent`

```json
{
  "action": "create",
  "schedule_id": 1,
  "title": "Подготовить презентацию",
  "description": "Сделать слайды проекта",
  "deadline": "2026-12-10",
  "priority": "high"
}
```

Пример добавление задачи со стороны Оркестратора:
```Python
self.task_agent.run({
    "action": "create",
    "schedule_id": 1,
    "title": "Подготовить презентацию",
    "description": "Сделать слайды для проекта",
    "deadline": "2026-10-28",
    "priority": "high"
})
```
В `schedule_id` укажите существующее расписание. Приоритеты: `low`, `medium`, `high`. Статусы: `pending`, `in_progress`, `completed`. Если статус не указан, будет `pending`, если приоритет не указан — `medium`.

### Получить данные через TaskAgent

Все запросы в этом разделе отправляются на `POST /api/task-agent` с JSON-телом.

**Получить все задачи и события расписания № 1** (`get` по умолчанию возвращает `all`):

```json
{
  "action": "get",
  "schedule_id": 1
}
```

В ответе есть общий массив `items`, отдельные массивы `tasks` и `events`, а также `count`. Каждый элемент содержит `schedule_id`, чтобы было ясно, к какому расписанию он относится.

**Получить только задачи или только обычные события:**

```json
{
  "action": "get",
  "schedule_id": 1,
  "item_type": "task"
}
```

```json
{
  "action": "get",
  "schedule_id": 1,
  "item_type": "event"
}
```

Допустимые значения `item_type`: `task`, `event`, `all`. Если не передавать `schedule_id`, `get` вернёт элементы из всех расписаний.

**Получить один элемент по ID:** для ID задачи используйте `task_id`, для обычного события — `event_id`. Универсальный `item_id` ищет любой тип элемента, но только внутри указанного расписания.

```json
{
  "action": "get",
  "schedule_id": 1,
  "task_id": 3
}
```

```json
{
  "action": "get",
  "schedule_id": 1,
  "event_id": 1
}
```

Важно: `task_id` — это ID именно задачи, а не расписания и не обычного события. В демонстрационном `schedules.json` ID `1` в расписании № 1 принадлежит событию «Спорт», а ID задачи «Подготовить презентацию» — `3`.

**Для чтения используется действие `get`.** По умолчанию оно возвращает все задачи и обычные события выбранного расписания. Чтобы получить только задачи, передайте `"item_type": "task"`; для обычных событий — `"item_type": "event"`.

```json
{
  "action": "get",
  "schedule_id": 1,
  "item_type": "task"
}
```

### Создать, изменить или удалить задачу

**Создать задачу:**

```json
{
  "action": "create",
  "schedule_id": 1,
  "title": "Подготовить презентацию",
  "description": "Сделать слайды проекта",
  "deadline": "2026-12-10",
  "priority": "high"
}
```

**Изменить задачу:**

```json
{
  "action": "update",
  "schedule_id": 1,
  "task_id": 3,
  "status": "completed"
}
```

**Удалить задачу:**

```json
{
  "action": "delete",
  "schedule_id": 1,
  "task_id": 3
}
```

Для изменения и удаления нужны оба ID: `schedule_id` и `task_id`. Приоритеты: `low`, `medium`, `high`; статусы: `pending`, `in_progress`, `completed`.

### Вызов TaskAgent через OrchestratorAgent

Оркестратор теперь передаёт структурированные запросы с `action` в `TaskAgent`. Например:

```python
from Application.Agents.OrchestratorAgent.Agent import OrchestratorAgent

orchestrator = OrchestratorAgent()

# Получить все задачи и обычные события выбранного расписания.
result = orchestrator.run({
    "action": "get",
    "schedule_id": 1,
    "item_type": "all",
})

if result["status"] == "ok":
    print(result["items"])
else:
    print(result["message"])
```

**Получить одну задачу:**

```python
result = orchestrator.run({
    "action": "get",
    "schedule_id": 1,
    "task_id": 3,  # ID задачи, не расписания
})

if result["status"] == "ok":
    print(result["item"])
else:
    print(result["message"])
```

Это тестирование структурированных действий. Обработка свободного текста вроде «перенеси лекцию на среду» пока не реализована: запрос с полем `command`, но без `action`, вернёт статус `not_implemented`.

## Что пока не реализовано

- Преобразование свободного текста в действия `TaskAgent`.
- Автоматическое размещение задач на временной шкале.
- Полноценная проверка пересечений событий и задач.
- Полноценная логика `PlannerAgent`, `ConflictAgent` и `ExplanationAgent` — сейчас это заготовки.

Следующий логичный этап — добавить интерпретацию команды, которая будет преобразовывать запрос пользователя в структурированное действие, например `{"action":"create", "schedule_id":1, "title":"..."}`, и передавать его в `TaskAgent`.
