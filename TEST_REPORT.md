# Отчёт о проверке Secretary-LLM

Дата проверки: 2026-10-24.

## Итог

**После исправлений пройдено 48 из 48 автоматических тестов.** Перед исправлениями один из 30 существующих тестов падал: в `OrchestratorAgent.run()` маршрутизация структурированных действий была заключена в многострочную строку и потому не исполнялась. Код маршрутизации восстановлен.

## Что проверено

### TaskAgent и база данных

- `get` возвращает задачи, события или все элементы расписания; можно запросить одно событие/задачу по соответствующему ID.
- Получение из выбранного расписания и из всех расписаний.
- Создание, изменение и удаление задач; операции с задачами не удаляют и не изменяют обычные события.
- Фильтры по `priority` и `status`, а также проверки допустимых значений.
- Отсутствующие, неправильные, дробные, булевы и неоднозначные ID.
- Несколько ID в одном запросе — запрос отклоняется, данные не меняются.
- Неизвестные поля при создании/изменении, неверные типы фильтров и дедлайнов.
- Дедлайн должен быть ISO-датой `YYYY-MM-DD`; пустой дедлайн очищает дату.
- Ошибка при повреждённом JSON возвращается как контролируемый ответ.
- Чтение не меняет данные в хранилище.
- Стресс-проверка: 80 последовательных созданий с обновлением и удалением части задач.
- Проверка конкуренции: 30 параллельных созданий без дублирования ID.

### Оркестратор, Flask и Frontend

- Структурированный запрос `action` действительно маршрутизируется в `TaskAgent`.
- Свободный текст не выдаётся за успешно выполненное действие: пока возвращается `not_implemented`.
- Flask test client: `/health`, `/`, `/static/styles.css`, API расписаний и задач, валидация JSON-тел и операции с событиями.
- Python-модули компилируются без ошибок.
- Встроенный JavaScript из реально отрендеренной главной страницы проходит `node --check`.
- В Chromium с отрендеренным шаблоном проверены открытие редактора кликом, отображение направляющих одинакового цвета, а также сворачивание/разворачивание окна. Полный сценарий браузерного перетаскивания через живой HTTP-сервер в этой среде не подтверждён: браузерная навигация на локальный адрес блокируется окружением. API операции проверены через Flask test client.

## Ограничения функциональности

- Естественный язык ещё не преобразуется в действия. Поле команды на сайте пока демонстрационное.
- `PlannerAgent`, `ConflictAgent` и `ExplanationAgent` остаются заглушками; поиск пересечений и автоматическое планирование ещё не реализованы.
- В `schedules.json` есть демонстрационные/отладочные данные (`ДА?`, `ТЫЦ`, `Тест таймлайна`). Перед общим пушем стоит решить, заменить ли их чистым `[]` или подготовить аккуратный общий пример.

## Обязательная уборка Git перед пушем

В исходном Git index уже отслеживаются **14 файлов `.pyc`**. Добавлен `.gitignore`, однако он не перестаёт отслеживать ранее добавленные файлы сам по себе. На исходной рабочей копии выполните из корня проекта, чтобы убрать байткод из индекса, сохранив файлы на диске:

```bash
git ls-files -z | grep -zE '(^|/)__pycache__/|\\.py[co]$' | xargs -0 -r git rm --cached --
```

Затем проверьте `git status`, убедитесь, что `schedules.json` содержит предполагаемые для команды данные, и только после этого коммитьте.
